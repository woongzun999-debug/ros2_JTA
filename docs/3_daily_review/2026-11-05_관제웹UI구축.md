## 2. 시간대별 작업 및 실전 트러블슈팅 내역

### 2.1 [13:30] WebUI (:9999) 상주 웹 인프라 및 실시간 단절 Watchdog 엔진 구축
- **작업 내용**:
  - `systemd --user` 데몬에 `jta-web-monitor.service`를 등록하여 부팅 시 자동 기동(`Linger=yes`) 구현.
  - 1초 주기 타이머(`watchdog_timer`)로 노드별 수신 타임스탬프를 상시 감시하여 3.0초 초과 미수신 시 화면을 `NO CONNECT` 경고 모드로 즉각 전환.

### 2.2 [17:55] 트러블슈팅: MJPEG 영상 스트림 정체 및 포트 충돌(`Errno 98 Address already in use`)
- **발생 시각**: 2026-11-05 17:55:17 KST
- **현상**: WebUI 화면 갱신 시 기기 텔레메트리(전압/라이다)는 정상이나 카메라 스트림(`/video_feed`)이 로딩 중 멈추거나 검은 화면으로 유지됨.
- **원인 분석**:
  1. 백그라운드에 이전에 실행된 구버전 `mobile_web_server` 프로세스 3개가 포트 9999 소켓을 물고 있어 신규 서비스가 바인딩 충돌(`Errno 98`)을 일으킴.
  2. `multipart/x-mixed-replace` 스트리밍 시 HTTP 파트 바운더리 헤더 규격 및 버퍼 flush 누락으로 브라우저 `<img>` 태그가 프레임을 분리 인식하지 못함.
- **해결 조치**:
  1. **Pre-Clean 격리**: `docker exec ros2_humble_basic pkill -9 -f mobile_web_server` 및 호스트 좀비 프로세스 완벽 강제 종료.
  2. **정격 헤더 및 flush 적용**: `--frame\r\nContent-Type: image/jpeg\r\nContent-Length: ...\r\n\r\n` 바이너리 블록 직접 구성 및 `wfile.flush()` 호출로 브라우저 즉각 렌더링 복구 성공.

### 2.3 [18:03] WebUI 데스크톱 레이아웃 1열 세로 스택 최적화
- **작업 내용**:
  - 데스크톱 와이드 화면에서 우측 3-Tier 하드웨어 카드들이 2열(`xl:grid-cols-2`)로 쪼개져 작게 보이던 구조를 **1열 세로 스택 (`flex flex-col gap-3.5`)**으로 전면 개편하여 카드 가로폭 최대 활용 및 시인성 극대화.

### 2.4 [18:25] 트러블슈팅: 영상 내 YOLO 바운딩 박스 누락 및 아키텍처 정합성 복원
- **발생 시각**: 2026-11-05 18:25:00 KST
- **현상**: 카메라 스트림은 나오나 젯슨이 감지한 물체의 바운딩 박스가 영상에 표시되지 않음.
- **원인 분석**:
  - 패스스루 전환 과정에서 노트북 웹서버의 OpenCV 드로잉 코드가 바이패스되어 순정 카메라 프레임만 송출됨.
  - 하네스 원칙상 젯슨(Tier 2)은 무거운 영상 재인코딩 없이 0.1ms JSON만 쏘고, 노트북(Tier 3)이 이를 받아 화면에 합성해야 함.
- **해결 조치**:
  - 파이 5 원본 프레임 디코딩 ➔ 젯슨의 `/yolo/detections` 최신 JSON 좌표(`box`, `center`, `conf`, `class_name`) 실시간 매핑.
  - 고대비 네온 바운딩 박스 + 중심점 십자선 타겟 마커 + 라벨 텍스트 드로잉 후 Quality 75로 웹 스트리밍 인코딩 복원 완료.
